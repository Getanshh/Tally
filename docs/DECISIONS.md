# Business decisions

Answers from the owner (2026-11-16) to the Phase 0 open questions. These drive validation and
posting rules. Change this file whenever a decision changes.

| #   | Topic                 | Decision                                                                                                                    | Effect on the build                                                                                                                                                                           |
| --- | --------------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Voucher type names    | Tally defaults: `Purchase Order`, `Sales`, `Purchase`                                                                       | Used as defaults for `ALLOWED_VOUCHER_TYPES` / `OPTIONAL_VOUCHER_TYPES`. Still checked exactly against the voucher-type masters                                                               |
| D2  | Price levels          | Each party can have its own price level. If a party has none, the item's **standard rate** applies                          | Rate order: party's price level → standard selling rate → reject (no rate means no proposal). Claude's rate is only compared                                                                  |
| D3  | Godowns               | More than one godown                                                                                                        | Godown is required on every inventory line and must match a godown master exactly. No silent default                                                                                          |
| D4  | Batches / expiry      | Not tracked today; **you want to start tracking**                                                                           | Code supports both: items with batches turned on need a batch (and expiry, if the item uses it); other items reject a batch. Turn batches on in the TEST company first (see SETUP-WINDOWS 5a) |
| D5  | GST registrations     | One GSTIN, Gujarat                                                                                                          | Company state comes from Tally (expected Gujarat). Gujarat party → CGST + SGST; any other state → IGST                                                                                        |
| D6  | Companies             | Live: `Baijay International Private Limited`. TEST: to be confirmed (suggested `Baijay International Private Limited TEST`) | Live company must **never** appear in `WRITE_ALLOWED_COMPANIES` during development; the capture script refuses names without TEST                                                             |
| D7  | Purchase invoice ↔ PO | Purchase invoices **must** link to a PO; partial receipts against a PO are tracked                                          | `propose_purchase_invoice` needs a PO. Qty is checked against the PO's pending qty, and rate comes from the PO                                                                                |
| D8  | Idempotency reference | Proposal ID goes in the voucher **Reference** field                                                                         | Duplicate check looks up Reference before posting; read-back verifies it                                                                                                                      |
| D9  | Second approval       | ₹1,00,000 threshold confirmed                                                                                               | `SECOND_APPROVAL_THRESHOLD_INR=100000`                                                                                                                                                        |
| D10 | Tally version         | TallyPrime 6                                                                                                                | Fixtures and VERIFY items are checked against TallyPrime 6                                                                                                                                    |
